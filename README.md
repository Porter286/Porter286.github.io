# Junqi Zhang · 学术与技术个人网站

一个可以直接打开、修改并发布到 GitHub Pages 的静态网站。使用 HTML5、CSS3 和原生 JavaScript，无需安装网站依赖或执行构建。

## 开发阶段与验收

| 阶段 | 工作 | 完成标准 | 当前情况 |
| --- | --- | --- | --- |
| 1 · 内容与设计 | 确定六个首页区块、内容边界、Minimal Light 视觉 | 信息层级清晰，未确认事项可识别 | 已实现首版 |
| 2 · 首页 | 语义化 HTML、响应式 CSS、轻量 JS | 六区块齐全；窄屏菜单；无 JS 仍可阅读与导航 | 已实现 |
| 3 · 内容与详情页 | 核实项目、经历、技能、公开联系方式 | 每项成果都有真实材料；项目链接指向完整详情页 | 待补材料 |
| 4 · 发布准备 | 路径、页面结构、键盘、屏幕尺寸、部署入口 | 无失效链接；键盘可用；手机和桌面人工复核 | 本地检查通过，范围见 CHECKS.md |
| 5 · GitHub Pages | 公共个人站仓库，main / root | 部署成功；实际网址和移动端复查通过 | 待发布 |

Minimal Light 在这里指已确认的视觉风格；本项目没有安装同名 Jekyll 主题。当前方案更便于学习 HTML/CSS，也符合直接从仓库根目录发布的要求。若课程明确要求使用该 Jekyll 主题，需要另行迁移。

## 第一步：本地打开首页

解压交付的 ZIP，双击 `index.html` 即可查看，样式和交互不依赖网络。

如需通过本地 HTTP 预览，在这个文件夹内打开终端并执行：

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8000`。预览结束后按 Ctrl+C 停止。若本机没有 Python，直接打开 HTML 或使用编辑器的静态预览功能即可。`404.html` 返回首页的 `/` 是为目标个人站根域名准备的；用文件方式打开该错误页时请直接打开旁边的 `index.html`。

## 第二步：理解文件分工

```text
index.html           首页内容与语义结构；首先编辑这里
assets/styles.css    全站配色、字体、间距和响应式布局
assets/main.js       手机菜单、当前区块导航、页脚年份
assets/favicon.svg   浏览器标签图标
404.html             自定义错误页，面向个人站根域名
.nojekyll            禁用 Jekyll 处理，直接发布静态文件
README.md            中文开发与发布指导
```

HTML 决定“内容是什么”；CSS 决定“如何呈现”；JavaScript 只增强交互。项目简介使用原生 `<details>`，关闭 JavaScript 后仍能展开。没有头像占位图、假邮箱、虚构社交账号或无效下载按钮。

## 第四步：调整视觉

在 `assets/styles.css` 顶部修改 CSS 变量即可调整全站。默认背景 `#FAFAF8`、正文 `#171717`、次灰 `#777777`、边框 `#DADAD6`、点缀 `#526A7B`。指定的 `#777777` 与米白搭配时，小字对比度不足 WCAG AA 普通文本要求，因此正文次级灰使用稍深的 `#696965`；原次灰保留为设计变量。

使用系统无衬线字体搭配本机衬线字体，不加载外部字体。电脑端为宽松的两栏 Hero 和带左侧章节标签的内容区；720px 以下变为单栏与折叠菜单，1000px 以下收紧间距。

键盘 Tab 可访问菜单、锚点和项目简介；Enter/空格可展开简介，Escape 可关闭手机菜单。跳转到正文的链接仅在键盘聚焦时显示。开启系统“减少动态效果”后取消平滑滚动。

## 第五步：GitHub Pages 发布

先补齐你愿意公开的内容，再发布。预备研究和待确认项目也可以如实保留当前标签；联系方式可以暂不公开。

1. 登录 GitHub，确认真实用户名。展示名 Junqi Zhang 不等于 GitHub 用户名，不能据此推测仓库名称。
2. 新建 **Public** 仓库，命名为 `你的真实用户名.github.io`。这是个人站命名格式，大小写遵循 GitHub 文档指引。
3. 把**本文件夹内的内容**上传到仓库根目录；不要把 `junqi-academic` 文件夹作为外层目录上传。仓库第一层必须能看到 `index.html`、`assets`、`404.html` 和 `.nojekyll`。上传时检查隐藏文件 `.nojekyll` 是否遗漏。ZIP 本身不应上传代替网页文件。
4. 提交到 `main`。
5. 仓库 **Settings → Pages → Build and deployment**：Source 选择 **Deploy from a branch**，Branch 选择 **main**，目录选择 **/ (root)**，保存。
6. 等待部署完成，查看 Pages 页给出的实际地址，通常为 `https://你的真实用户名.github.io/`。以 GitHub 显示的状态为准。
7. 打开网站，检查菜单、项目简介、手机布局、资源加载，以及访问 `/missing-page` 是否进入自定义 404 并可返回首页。

官方依据：[创建 GitHub Pages 网站](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)、[GitHub Pages 快速入门](https://docs.github.com/en/pages/quickstart)。发布方式已按交付时官方文档核对；仓库和线上部署尚未创建或执行。

## 发布前人工检查

- 在 375px 手机、768px 平板及 1440px 桌面宽度查看：无横向溢出、遮挡或截断。
- 仅用键盘访问菜单、六个区块和项目展开；焦点应始终可见。
- 手机菜单展开后选取区块，再测试 Escape 关闭和调整窗口宽度。
- 浏览器放大到 200%，检查文字和导航可读。
- 禁用 JavaScript：内容、导航和项目简介仍然可用。
- 确认 Planned、项目状态、学历、技能和联系方式均准确。
- 不要宣称仅凭静态检查即已完成全套无障碍合规认证。
